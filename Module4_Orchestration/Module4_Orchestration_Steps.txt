LG NOIDA AI TRAINING — MODULE 4: AGENT ORCHESTRATION (STUDENT STEPS)
n8n instance: https://arjunthakurdev.app.n8n.cloud/
Saved: 2026-08-19

GOAL
Wire the three predictive-maintenance agents into ONE workflow so a single
question flows through all three and produces one final answer:
   Agent A (Failure Prediction) -> Agent B (Spare Parts) -> Agent C (Maintenance)
Pattern: SEQUENTIAL pipeline (simplest + most reliable for a live demo).

WHY A NEW WORKFLOW?
The three agents were each built in their OWN workflow. A sequential pipeline
must run on ONE canvas (each node feeds the next). So we assemble the three
tested agents into a single new workflow. We do NOT rebuild them — we COPY them.

---------------------------------------------------------------------
STEP 1 — COPY THE EXISTING AGENTS INTO ONE WORKFLOW
---------------------------------------------------------------------
1. Open the Agent A workflow.
2. Click the "AI Agent" node, then CTRL-CLICK its "Google Gemini Chat Model"
   node so BOTH are selected. (Ctrl-click adds to the selection — NOT shift-click.)
3. Ctrl+C to copy.
4. Create a new workflow -> name it "Module 4 — Orchestration (A->B->C)".
5. Ctrl+V to paste. Both nodes drop in with the system message intact.
6. Repeat steps 1-5 for Agent B and Agent C (paste all into the SAME new workflow).

You now have three agent+model pairs on one canvas.

---------------------------------------------------------------------
STEP 2 — NAME THE NODES
---------------------------------------------------------------------
Double-click each AI Agent node title and rename them:
   Agent A , Agent B , Agent C
(Clean names make the handoff expressions in Step 4 readable.)

---------------------------------------------------------------------
STEP 3 — ADD THE TRIGGER AND WIRE THE CHAIN
---------------------------------------------------------------------
1. Add a "When chat message received" (Chat Trigger) node.
2. Wire the main (left-to-right) connections:
      Chat Trigger -> Agent A -> Agent B -> Agent C
   (Drag from each node's right-side dot to the next node's left-side dot.)
Each agent keeps its OWN Gemini Chat Model attached underneath (same credential).

---------------------------------------------------------------------
STEP 4 — SET EACH AGENT'S "PROMPT" (THE HANDOFF) — the key step
---------------------------------------------------------------------
Double-click each agent and set its Prompt field:

Agent A:
   Prompt = "Take from previous node automatically"
   (It reads the question typed in the chat box.)

Agent B:
   Prompt = "Define below" -> toggle the field to EXPRESSION -> enter:
      {{ $json.output }}
   (This is Agent A's output = the predicted failure.)

Agent C:
   Prompt = "Define below" -> toggle to EXPRESSION -> enter these two lines:
      Predicted failure: {{ $('Agent A').item.json.output }}
      Parts status: {{ $('Agent B').item.json.output }}
   WHY BOTH? In a plain chain each node only sees the one before it, so Agent C
   would lose Agent A's failure lead time (needed for the "schedule by" date).
   This pulls in BOTH A's prediction and B's parts status.

---------------------------------------------------------------------
STEP 5 — SAVE AND TEST
---------------------------------------------------------------------
1. Save the workflow.
2. Click "Open Chat" (bottom of canvas).
3. Type:  Servo position error is now 140 counts and rising
4. Expected chain:
      Agent A -> encoder EN-77 degrading, ~6 days
      Agent B -> EN-77, 0 in stock, 21-day lead, URGENT
      Agent C -> maintenance request, schedule within 6 days, URGENT, escalate to Bay-3 lead
5. The chat window shows Agent C's final answer. To SHOW the handoff to the room,
   click each node afterwards and open its output (A -> B -> C each did its part).

---------------------------------------------------------------------
GOTCHAS
---------------------------------------------------------------------
- Multi-select = CTRL-CLICK nodes (not shift-click).
- Read the CHAT BUBBLE, not the raw output panel (raw shows escaped \n and *; normal).
- AI Agent output field is "output". If an expression returns blank, open the
  upstream node's output tab and confirm the field name.
- Each agent needs its OWN Chat Model sub-node; they can share the same credential.
- FALLBACK (if expressions are troublesome): edit Agent B's system message to
  RESTATE the predicted failure + add the parts status, then set Agent C's Prompt
  to just {{ $json.output }}. Less clean but avoids multi-node references.
- n8n is still marked TESTING — keep a SCREEN RECORDING of the working run as backup.

---------------------------------------------------------------------
ORCHESTRATION PATTERNS (for the concept slide)
---------------------------------------------------------------------
- Sequential (what we built): A -> B -> C, fixed order. Best when the flow is linear.
- Supervisor: one lead agent decides which sub-agents to call. Best when the flow
  is dynamic/conditional. More moving parts — describe it, don't demo it today.
- Parallel: agents run at the same time, results merged. For independent sub-tasks.
