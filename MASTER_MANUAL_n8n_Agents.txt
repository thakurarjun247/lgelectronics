========================================================================
PART 0 — TERMINOLOGY (read once)
========================================================================
- Workflow: the whole automation on one canvas (one screen of connected blocks).
- Node: a single block/step. Wired left -> right; data flows along the wires.
- Canvas: the editor screen.
- Trigger: the FIRST node; decides when the workflow runs. We use the Chat Trigger
  ("When chat message received"), which gives a live chat box.
- Execution / run: one time the workflow runs. n8n logs each run; click any node to
  see what it output.
- Credential: a saved secret (API key / Google login). Saved once, reused everywhere.
- AI Agent node: the "brain" (an LLM that reasons). It cannot run alone — you plug
  SUB-NODES into the slots underneath it:
     Chat Model (required) = which LLM (Google Gemini).
     Memory (optional)     = remembers the conversation.
     Tool / Output Parser (optional) = actions / structured output.
- System Message: the standing instructions baked into an agent (role + reference data).
- Sub-node vs normal node: the AI Agent is a normal node, but it has EXTRA bottom
  slots that sub-nodes plug into (they attach from underneath, not left->right).

VERSION NOTE: The AI Agent node no longer has an "agent type" selector (removed in
n8n v1.82.0). Every AI Agent runs as a "Tools Agent". Nothing to choose.

PART 4 — THE THREE SYSTEM PROMPTS (verified working, short)
========================================================================
--- AGENT A — FAILURE PREDICTION ---
You are the Failure Prediction Agent for IM-500 injection molding (Bay 3). Predict failures from sensor readings using ONLY this reference. If not covered, say so — don't guess.

Thresholds (Normal / Warning / Critical -> cause, lead time):
- Vibration mm/s: <2.8 / 2.8-4.5 / >4.5 -> pump bearing wear, ~7d
- Oil temp C: <50 / 50-60 / >60 -> pump/cooling wear, ~10d
- Heater drift C: +/-5 / 5-10 / >10 -> heater band ageing, ~14d
- Motor current A: 18-24 / 24-28 / >28 -> overload, ~5d
- Screw torque %: <70 / 70-85 / >85 -> screw/barrel wear, ~12d
- Tie-bar strain uE: <800 / 800-1000 / >1000 -> tie-bar wear, ~9d
- Servo error counts: <50 / 50-120 / >120 -> encoder EN-77, ~6d

Rules: Warning = predicted failure; Critical = immediate. Schedule maintenance before (today + lead time).

Output: failing component, lead time, urgency.

--- AGENT B — SPARE PARTS ---
You are the Spare Parts Agent for IM-500 (Bay-3 store). Given a failing component/part, return the exact part + stock using ONLY this reference. Don't invent parts or stock.

Component -> Part No (stock / min / lead / status):
- pump bearing -> BR-3105 (4/2/5d OK)
- pump seal -> SK-4620 (1/2/7d LOW)
- barrel heater -> HB-220 (3/2/6d OK)
- thermocouple -> TC-11 (0/1/4d OUT)
- cooling circuit -> CF-08 (6/3/3d OK)
- injection screw -> ST-90 (0/1/15d OUT)
- ejector -> EP-12 (2/1/5d OK)
- servo drive fan -> FN-40 (1/1/9d OK)
- servo encoder -> EN-77 (0/1/21d OUT)

Rules: stock < min -> reorder. If failure sooner than lead time -> URGENT/expedite. EN-77 always URGENT (21d lead vs ~6d failure), escalate to Bay-3 lead.

Output: part no, stock, lead time, reorder/urgent decision.

--- AGENT C — MAINTENANCE (base version; structured-output version in PART 8) ---
You are the Maintenance Agent for IM-500 injection molding (Bay 3). You receive a predicted failure and its spare-part status. Raise a maintenance request using ONLY that input — don't invent details.

Two different numbers may appear — keep them separate:
- FAILURE lead time = days until the machine fails.
- PART supply lead time = days to get the spare part.

Rules:
- "Schedule maintenance by" must be BEFORE the failure lead time (e.g. failure in 6 days -> schedule within 6 days). NEVER use the part supply lead time as the schedule date.
- If part is out of stock, or PART supply lead time > FAILURE lead time -> mark URGENT, add "escalate to Bay-3 lead", note the part may not arrive before failure.
- Otherwise NORMAL.

Output:
- Machine: IM-500 (Bay 3)
- Failing component:
- Part needed (part no. + stock status):
- Predicted failure in: (days)
- Schedule maintenance by: (before the failure, in days)
- Priority: NORMAL / URGENT (+ escalation note if urgent)

TEST INPUTS
Agent A: "Hydraulic pump vibration has been 3.9 mm/s for the last 4 shifts" -> pump bearing, ~7d.
         "Servo position error is now 140 counts and rising" -> encoder EN-77 (Critical), immediate.
Agent B: "Which parts are currently out of stock?" -> TC-11, ST-90, EN-77.
         "Servo encoder EN-77, failure predicted in 6 days" -> 0 stock, 21d lead, URGENT/escalate.
Agent C (standalone; simulate A+B): "Predicted failure: servo encoder EN-77 degrading, failure in ~6 days.
         Part EN-77 is 0 in stock, 21-day supplier lead time." -> schedule within 6d, URGENT, escalate.
GROUNDING CHECK (should refuse): Agent A "What's the coolant pressure threshold?" -> not in reference.

PART 5 — COMBINE ALL THREE INTO ONE WORKFLOW (orchestration)
========================================================================
A sequential pipeline must live on ONE canvas. You do NOT rebuild the agents — COPY them.

5.1 COPY THE AGENTS IN
1. Open the Agent A workflow.
2. Click the "AI Agent" node, then CTRL-CLICK its "Google Gemini Chat Model" node so BOTH
   are selected. (CTRL-click to multi-select — NOT shift-click.)
3. Ctrl+C.
4. Create a new workflow -> name it "Module 4 — Orchestration (A->B->C)".
5. Ctrl+V. Both nodes drop in with the system message intact.
6. Repeat 1-5 for Agent B and Agent C (paste all into the SAME new workflow).

5.2 NAME THE NODES
Double-click each AI Agent title and rename: Agent A, Agent B, Agent C.
(Clean names make the handoff expressions readable.)

5.3 ADD TRIGGER + WIRE THE CHAIN
1. Add "When chat message received" (Chat Trigger).
2. Wire the main (left->right) connections:  Chat Trigger -> Agent A -> Agent B -> Agent C.
Each agent keeps its own Gemini Chat Model attached underneath.

5.4 SET EACH AGENT'S "PROMPT" (the handoff — key step)
Agent A: Prompt = "Take from previous node automatically". (reads the chat question)

Agent B: Prompt = "Define below" -> toggle field to EXPRESSION -> enter:
         {{ $json.output }}
         (this is Agent A's output = the predicted failure)

Agent C: Prompt = "Define below" -> EXPRESSION -> enter these two lines:
         Predicted failure: {{ $('Agent A').first().json.output }}
         Parts status: {{ $('Agent B').first().json.output }}

WHY .first() AND NOT .item:
In a chain, each node normally only sees the node just before it. Agent C is TWO hops
from Agent A, and $('Agent A').item... returns blank across two hops (paired-item
tracking breaks). $('Agent A').first().json.output reads Agent A's output directly and
is reliable for a one-at-a-time demo.

COMMON ERROR: "No prompt specified / expected 'chatInput'" on Agent B or C means that
node's Prompt is still set to "Take from previous node automatically". Fix: set it to
"Define below" with the expression above. Only Agent A stays on auto.

5.5 TEST THE PIPELINE
Open Chat -> "Servo position error is now 140 counts and rising".
Expected: A -> encoder EN-77; B -> 0 stock, 21d, URGENT; C -> maintenance request,
schedule within failure window, URGENT, escalate to Bay-3 lead.
Contrast test -> "Hydraulic pump vibration has been 3.9 mm/s for the last 4 shifts"
-> ends NORMAL (BR-3105 in stock). URGENT vs NORMAL proves it is reasoning.

PART 6 — LOG THE DECISION TO A GOOGLE SHEET (the agent acts)
========================================================================
Stack: Google Sheets (native n8n node) + later Looker Studio. Excel/M365 is NOT used
(no license). Same Google account as Gemini.

6.1 CREATE THE SHEET
1. sheets.google.com -> Blank spreadsheet -> name it: IM500_Maintenance_Log
2. Row 1 headers (A1..H1), one per cell:
   Timestamp | Machine | Failing Component | Part No | In Stock | Failure In (days) | Schedule By (days) | Priority
3. Keep tab name Sheet1.

6.2 ADD + CONNECT THE GOOGLE SHEETS NODE
1. In the orchestration workflow -> add node -> search "Google Sheets".
2. Credential -> "Sign in with Google" -> complete popup -> allow access. (If popup is
   blocked, allow popups for the n8n domain.)
3. Configure:
   - Resource = Sheet Within Document
   - Operation = Append Row   (avoids the "Column to match on" requirement)
   - Document = From list -> IM500_Maintenance_Log
   - Sheet = From list -> Sheet1
   - Mapping Column Mode = Map Each Column Manually
     (Automatic only works if the input keys exactly match the header text — ours don't.)
4. Wire: Agent C -> Google Sheets node.

PART 7 — MAKE AGENT C OUTPUT STRUCTURED FIELDS (so columns are clean)
========================================================================
The Sheet needs discrete values (component, part, priority...). Agent C outputs prose,
so we attach a Structured Output Parser.

7.1 TURN ON STRUCTURED OUTPUT
1. Double-click Agent C -> switch ON the toggle "Require Specific Output Format".
   This adds an "Output Parser" slot under the node.

7.2 ADD THE PARSER
2. Click "+" under the "Output Parser" slot -> add "Structured Output Parser".
3. In it: Schema Type = "Generate From JSON Example" -> paste:
   {
     "machine": "IM-500 (Bay 3)",
     "component": "servo encoder EN-77",
     "part": "EN-77",
     "in_stock": 0,
     "failure_days": 6,
     "schedule_by_days": 6,
     "priority": "URGENT",
     "summary": "Raise URGENT maintenance for servo encoder EN-77; part EN-77 out of stock, 21-day lead exceeds 6-day failure — escalate to Bay-3 lead."
   }

7.3 UPDATE AGENT C SYSTEM MESSAGE OUTPUT SECTION
Replace only the "Output:" section of Agent C's prompt with:
   Output these fields:
   - machine: "IM-500 (Bay 3)"
   - component: the failing component
   - part: part number
   - in_stock: number in stock
   - failure_days: days until failure (number)
   - schedule_by_days: days to schedule by — must be less than failure_days (number)
   - priority: NORMAL or URGENT
   - summary: one-line human-readable maintenance request (include escalation note if urgent)
(Keep the FAILURE vs PART lead-time rules above it unchanged.)
NOTE: the chat reply now shows a structured object instead of the bullet list; the
"summary" field preserves a human-readable line.

7.4 VERIFY FIELD PATH
Run the servo test -> click Agent C -> output tab. Confirm fields sit under "output"
(so {{ $json.output.component }}). If they sit at top level, drop ".output" in the maps.

PART 9 — DASHBOARD (INSIDE GOOGLE SHEETS)  [DONE]
========================================================================
DECISION: build the dashboard as a TAB inside the same Google Sheet, NOT in Looker
Studio. Reason: Sheets charts update INSTANTLY when a row is added (Looker Studio
caches Sheet data up to ~15 min — wrong for a live demo), one less tool/login to break,
and simpler to explain. (Looker Studio only wins if you need a shareable exec URL.)

REQUIRED: Agent C's Priority must be a CLEAN value ("URGENT" or "NORMAL" only) and
Part No must be the code only. Otherwise COUNTIF exact-match and the traffic-light
formatting fail. (See PART 7.3 — put escalation notes in "summary", not "priority".)

9.1 SEED THE LOG (optional, so the dashboard looks rich)
- Paste the 12 seed rows (file: Module5_Dashboard/IM500_Maintenance_Dashboard.xlsx,
  Sheet1 tab, rows 2-13) under the headers in your live Sheet1, starting at A2.
- Component names in the seed match the bar chart exactly.

9.2 IMPORT THE DASHBOARD TAB (into the SAME spreadsheet)
- File: Module5_Dashboard/IM500_Dashboard_TAB_ONLY.xlsx (Dashboard tab only; its
  formulas reference Sheet1).
- In the live spreadsheet: File -> Import -> Upload -> that file ->
  Import location = "Insert new sheet(s)" -> Import data.
- A "Dashboard" tab appears, wired to Sheet1.
- REQUIREMENT: the live data tab must be named exactly "Sheet1".

9.3 WHAT THE DASHBOARD CONTAINS
- KPI tiles: Total Requests / URGENT / NORMAL  (=COUNTA / =COUNTIF on Sheet1).
- Pie: Requests by Priority.
- Column chart: Failures by Component (EN-77 is the repeat offender).
- All update live as new rows land (no refresh needed).

9.4 TRAFFIC-LIGHT THE LOG (do once, on Sheet1)
- Select column H (Priority) -> Format -> Conditional formatting ->
  Text is exactly "URGENT" -> red ; add rule "NORMAL" -> green.

9.5 IF A CHART DOESN'T RENDER AFTER IMPORT
- Google usually converts the Excel pie/bar fine. If not, the helper tables are already
  on the Dashboard tab (A7:B9 priority, D7:E14 component) -> select one -> Insert -> Chart.
- KPIs and formulas always survive import.

BUILD-YOUR-OWN (if not importing the file):
1. New tab named "Dashboard".
2. KPIs:  A1 "Total Requests" B1 =COUNTA(Sheet1!C2:C1000)
          A2 "URGENT"         B2 =COUNTIF(Sheet1!H2:H1000,"URGENT")
          A3 "NORMAL"         B3 =COUNTIF(Sheet1!H2:H1000,"NORMAL")
3. Priority pie: helper D1 URGENT E1 =B2 ; D2 NORMAL E2 =B3 -> Insert -> Chart -> Pie.
4. Component bar: Insert -> Pivot table (Sheet1!A1:H1000), Rows = Failing Component,
   Values = COUNTA -> select pivot -> Insert -> Chart -> Column.
